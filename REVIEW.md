# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (line 73–74) | Always returns 200 regardless of whether MongoDB is reachable. The contract requires 503 when MongoDB does not answer. | Shut down MongoDB and call `GET /health`; still receives `{"status": "ok"}` with 200. | Added `client.admin.command("ping")` inside a try/except; raise `HTTPException(503)` on failure. |
| 2 | `list_employees()` — `skip` calculation (line 93) | `skip = page * page_size` is off-by-one. Page 1 skips the first `page_size` documents, so the first page is empty and the second page returns what should be the first page. | Call `GET /employees?page=1`; result is empty even though documents exist. | Changed to `skip = (page - 1) * page_size`. |
| 3 | `list_employees()` — `total` ignores filter (line 94) | `total = db.employees.count_documents({})` counts the entire collection regardless of the `department` filter, so the total is wrong when filtering. | Filter by a department with fewer employees than the total; `total` in the response is too large. | Changed to `total = db.employees.count_documents(q)`. |
| 4 | `list_employees()` — no sort (line 95) | Documents are returned in natural MongoDB insertion order, not sorted by `emp_code` ascending as the contract requires. | Insert employees out of alphabetical order, then list them; order is insertion order. | Added `.sort("emp_code", ASCENDING)` to the cursor. |
| 5 | `punch_in()` — no 404 for unknown employee (lines 101–121) | `emp = db.employees.find_one(...)` can return `None`, but the code immediately calls `emp["shift_start"]` without checking, raising an unhandled `TypeError` (which FastAPI surfaces as 500). | Send a punch-in for a non-existent `emp_code`; receive 500 instead of 404. | Added `if not emp: raise HTTPException(404, "employee not found")`. |
| 6 | `punch_in()` — timestamp is naive and treated as local time (line 102) | `datetime.fromtimestamp(body.punched_at / 1000)` creates a naive datetime using the **local system timezone**, not UTC. IST date calculation is then wrong for any timezone that isn't IST. | Run the server on a UTC host and punch in at a time that straddles midnight IST; the attendance date is one day off. | Replaced with `datetime.fromtimestamp(ms // 1000, tz=timezone.utc)`, which always produces a UTC-aware datetime. |
| 7 | `punch_in()` — attendance date does not implement R1 overnight rule (line 103) | `d = ts.date().isoformat()` always uses the wall-clock date of the punch-in. For an overnight shift (e.g. 22:00–06:00), a punch at 03:00 IST should have the previous day's date. | Create an employee with `shift_end <= shift_start` (overnight), punch in after midnight; the date is wrong. | Introduced `compute_attendance_date()`, which detects overnight shifts and subtracts one day when the IST time of the punch-in is before `shift_end`. |
| 8 | `compute_late_minutes()` — grace-period boundary is wrong (line 37) | `return minutes if minutes > 10 else 0` compares floor-minutes, not the exact elapsed seconds. A punch at 09:40:01 (1 second past grace) yields `minutes = 10`, which is not `> 10`, so it returns 0 instead of 10. The rule says "strictly more than 10:00" — 10 minutes 1 second **is** late. | Punch in at exactly 09:40:01 with shift_start=09:30; `late_minutes` is 0 but should be 10. | Rewrote to compare `elapsed_seconds <= 600` (i.e. ≤ 10 minutes not late) before doing integer division, matching the examples in R2. |
| 9 | `compute_overtime()` — date parsing creates a naive datetime (line 46) | `datetime.fromisoformat(date_str).replace(hour=h, minute=m, tzinfo=IST)` depends on the caller passing a correctly formatted string AND does not handle overnight shifts. For overnight shifts the shift_end is on the next calendar day; the function always uses the attendance date. | Create an overnight-shift employee, punch out past shift_end on the next day; overtime is negative (or wildly wrong). | Replaced with `compute_overtime_with_employee()`, which accepts both `shift_start` and `shift_end` to detect overnight shifts and places `shift_end` on the correct calendar day. |
| 10 | `list_attendance()` — loads entire collection into memory (lines 144–150) | `docs = list(db.attendance_logs.find(q))` fetches all matching documents before slicing in Python. On 100 000 records this is extremely slow and memory-hungry. `total = len(docs)` counts after Python-side slicing, which is also incorrect. | Call `GET /attendance` on a large dataset; response is slow and `total` can be wrong when pagination is used. | Replaced with `db.attendance_logs.count_documents(q)` for the total, and `.sort(...).skip(skip).limit(page_size)` on the cursor so the DB does all filtering and pagination. |
| 11 | `list_attendance()` — `total` computed after slicing (line 146) | After the bug in #10, `total = len(docs)` is the count of all matching documents (before slicing), but this is only correct because `docs` is fetched in full. If the fetch were paginated first, `total` would be wrong. The fix in #10 makes this explicit: use `count_documents(q)`. | Already described in #10. | Fixed as part of #10. |
| 12 | `create_employee()` — race condition on duplicate `emp_code` (lines 79–80) | `if db.employees.find_one(...): raise 409` is a check-then-insert pattern. Two concurrent requests for the same `emp_code` can both pass the check and both succeed, creating duplicates. | Send two simultaneous POST /employees with the same `emp_code`; both return 201. | Removed the `find_one` check. Rely entirely on the unique index and catch `DuplicateKeyError`, which is atomic. |
| 13 | `punch_in()` — race condition on duplicate punch-in (line 104) | Same check-then-insert pattern as #12. Two simultaneous punch-ins for the same employee and date can both pass the `find_one` check and both insert. | Send two simultaneous punch-ins for the same employee+date; both return 201 instead of one 201 and one 409. | Removed the `find_one` check. Rely on the unique compound index `(emp_code, date)` and catch `DuplicateKeyError`. |
| 14 | `create_employee()` — `created_at` stored as naive local datetime (line 82) | `datetime.now()` returns a naive datetime in the server's local timezone. The contract says instants are stored as UTC BSON datetimes and returned as epoch milliseconds. | On a non-UTC server, `created_at` is stored with the wrong offset; returned millisecond value is incorrect. | Changed to `datetime.now(tz=timezone.utc)` and serialised to milliseconds before returning. |

## Items examined and decided NOT to be defects

- **`compute_late_minutes` using `int(.../ 60)` for floor division** — intentional; `int()` truncates toward zero, which matches `floor` for positive values.  
- **`PunchInIn.punched_at` accepting `None`** — correct; the spec says the field is optional and defaults to now.  
- **`db.attendance_logs.find(q)` projection omission** — the starter omits `{"_id": 0}` and pops `_id` inside the loop instead; functionally equivalent for the list endpoint (though the fixed code uses `{"_id": 0}` in the projection for clarity).
